Arc Lab

Two exercises on places where Arc behaves differently from Ethereum. You deploy a contract, submit its address, and a checker contract on Arc tests it. Pass or fail is written to the chain, so anyone can check your result on the explorer.

How it works:

  1. Connect a wallet. If your instructor enrolled you, you already have 0.1 USDC for gas.
  2. Deploy the starter contract for an exercise and submit it. It fails on purpose, and the page tells you why.
  3. Fix it in Remix or Foundry, deploy your version, and submit that.

1. Books that balance

Status: Not attempted

Background

On Arc, native USDC and the USDC token at 0x3600…0000 are the same balance, read two ways:

address(vault).balance   1.000000000000000005   // native, 18 decimals
USDC.balanceOf(vault)    1.000000               // token, 6 decimals

Two things follow. A token transfer to your contract raises its native balance without running any of its code. And the token view rounds down anything under 0.000001 USDC, so the last 12 digits above are invisible to it.

Task

Write a vault that reports its real balance and can pay all of it out.

function learner() external view returns (address);
function deposit() external payable;
function totalAssets() external view returns (uint256); // wei, 18 decimals
function withdrawAll(address payable to) external;

How it is graded

The checker deposits a random amount that includes dust, sends 0.000001 USDC with a token transfer, reads totalAssets(), then calls withdrawAll and checks nothing is left. The whole test runs inside a call that is reverted afterwards, so no money actually moves.

Steps

  1. Deploy the starter vault (it has two bugs).

  3. Fix the starter and deploy it yourself, with your wallet address as the constructor argument. Submit the new address in step 2.

2. Post-quantum signature

Status: Not attempted

Background

Arc can verify SLH-DSA-SHA2-128s signatures, a post-quantum scheme, through a precompile at 0x1800…0004. Keys are 32 bytes and signatures are 7,856 bytes.

Task

Sign a message that names your address with your own key, and deploy a contract that checks signatures with the precompile. It must accept your signature and reject a copy with one byte changed.

function learner() external view returns (address);
function verify(bytes calldata vk, bytes calldata message, bytes calldata sig)
    external view returns (bool);

Steps

  1. Sign your message. The page makes a new key in your browser and signs the exact message the checker expects from your address. The key is not saved or sent anywhere.

  2. Deploy the starter verifier (it only checks input lengths).

  4. Fix the starter so verify calls the precompile, deploy it with your address as the constructor argument, and submit it in step 3.
